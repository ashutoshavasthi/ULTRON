1. Number Systems & Conversions

A number system is a way of writing numbers using a fixed set of symbols (digits). The count of distinct digits is the base (also called radix, written r). A number is written (N)r, meaning "N written in base r".

1.1 Positional (weighted) notation

In every positional system, each digit is multiplied by a power of the base that depends on its position. Positions to the left of the point have powers r0, r1, r2…; positions to the right have r-1, r-2….

(dn … d1 d0 . d-1 d-2 …)r = Σ di × ri

Your notes' example: (56)10 = 5×101 + 6×100.

2. Subtraction Using Complements

Computers have no separate subtractor in the CPU's core: they turn A − B into A + (complement of B) and reuse the adder. There are two complements for any base r:

NameBinary (r=2)Decimal (r=10)How to get it (n-digit number N)
Radix complement (r's)2's complement10's complementrn − N
Diminished radix complement ((r−1)'s)1's complement9's complement(rn − 1) − N
Fast hand methods
  • 1's complement: flip every bit (0↔1). Equivalent: 9's complement = subtract every digit from 9.
  • 2's complement: 1's complement + 1. Shortcut: copy bits from the right up to and including the first 1, then flip all bits to the left.
  • 10's complement = 9's complement + 1 (add 1 at the last digit).

2.1 Subtraction by 2's complement (radix complement)

  1. Equalise digits: pad the shorter number with leading zeros so both have the same number of digits.
  2. Complement the subtrahend (the number being subtracted) → take its 2's complement.
  3. Add it to the minuend.
  4. Look at the end carry (EOC / end-around carry):
    • Carry generated → result is positive and correct. Discard (ignore) the carry.
    • No carry → result is negative and is in 2's-complement form. Take the 2's complement of the sum and put a minus sign (your note: "if EAC not generated, 2's complement again, put −ve sign").
Example 2.1 — 101101 − 11011 (your notes' example; 45 − 27)
Minuend X = 101101 Subtrahend Y = 11011 → pad → 011011 2's comp of Y: flip → 100100, +1 → 100101 101101 + 100101 --------- 1 010010 ← carry generated → ignore it 010010 = 10010 = 18 ✓ (45 − 27 = 18)
Example 2.2 — 011011 − 101101 (27 − 45, a negative answer)
2's comp of 101101: flip → 010010, +1 → 010011 011011 + 010011 --------- 101110 ← no carry → answer is negative 2's comp of 101110: flip → 010001, +1 → 010010 = 18 → result = −18 ✓

2.2 Subtraction by 1's complement (diminished radix)

Same steps, but with the 1's complement, and the carry rule is different:

  1. Pad to equal length; take the 1's complement of the subtrahend; add.
  2. Carry generated → add that carry to the LSB of the sum (end-around carry); the result is positive.
  3. No carry → take the 1's complement of the sum and put a minus sign.
Example 2.3 — 101101 − 011011 with 1's complement
1's comp of 011011 = 100100 101101 + 100100 -------- 1 010001 ← carry out → wrap around: 010001 + 1 = 010010 = 18 ✓
Example 2.4 — 011011 − 101101 with 1's complement
1's comp of 101101 = 010010 011011 + 010010 = 101101 ← no carry 1's comp of 101101 = 010010 = 18 → −18 ✓

2.3 The same idea in decimal (10's and 9's complement)

Example 2.5 — 463.42 − 546.001 using 10's complement (your notes)
Step 1 — equal digits: X = 463.420, Y = 546.001 Step 2 — 10's comp of Y: 9's comp = 453.998, +0.001 → 453.999 Step 3 — add: 463.420 + 453.999 = 917.419 ← no carry out Step 4 — no carry ⇒ negative: 10's comp of 917.419 9's comp = 082.580, +0.001 → 082.581 Answer = −82.581 check: 463.42 − 546.001 = −82.581 ✓
MnemonicCarry → positive → drop it (r's) or add it back (r−1's). No carry → negative → complement the sum again and write "−". "Radix complement discards, diminished radix wraps around."

Why does it work? A − B = A + (rn − B) − rn. The extra rn shows up as the carry out of the n-th digit, so discarding the carry removes it. If A < B, the sum is rn − (B−A), i.e. the complement of the (negative) answer — hence complement it back.

3.3 Overflow

If the true result doesn't fit in n bits, the answer is wrong. For 2's-complement addition: overflow occurs when two operands of the same sign give a result of the opposite sign (equivalently carry into the MSB ≠ carry out of the MSB). Adding numbers of opposite sign can never overflow.

Example 3.2 — 4-bit: 5 + 6

3.4 Sign extension

To widen a 2's-complement number copy the sign bit leftwards: 1010 (−6) → 11111010 (−6); 0110 (+6) → 00000110.

4.4 Two-level implementation (SOP with NAND-NAND)

A two-level circuit has an AND level feeding one OR level (sum of products). To convert to NAND only: replace every gate by a NAND. Why it works: draw a NAND as a bubbled OR; the bubble on each first-level NAND output and the bubble at the second-level inputs cancel ("put two bubbles always" in your note).

Example 4.2 — f = A·B + A·C with NAND gates (your notes)
AND–OR (SOP)
NAND–NAND (same function)
f = ((A·B)' · (A·C)')' = (AB)'' + (AC)'' = AB + AC (De Morgan on the last NAND)

Rule: SOP → NAND–NAND. Likewise POS → NOR–NOR (OR level then AND level; each replaced by NOR). If a literal feeds the 2nd level directly (e.g. f = AB + C), pass C through an inverter (a NAND with tied inputs) or equivalently feed C' — otherwise the double-bubble rule breaks.

4.5 Multi-level implementation

If the expression is allowed to have more than two levels (factored form such as A(B+C) or (A+B)(C+D)E) there is no need to convert to SOP or POS: implement the expression as it stands. It often needs fewer gates and fan-in but takes more gate delays (slower). Trade-off: two-level = fast, multi-level = small.

5. Boolean Algebra

Boolean algebra is algebra over the two-element set {0,1} with operations + (OR), · (AND) and ' (NOT). Every digital circuit corresponds to a Boolean expression, and simplifying the expression simplifies the circuit.

5.1 Basic laws (definitions)

Inverse (complement)x + x' = 1x·x' = 0

Watch outThe second distributive law (+ over ·) is false in ordinary algebra but true in Boolean algebra. Examiners love it.

5.2 Duality principle

The dual of a Boolean expression is obtained by interchanging + ↔ · and 0 ↔ 1 (variables and complements stay). If an identity is true, its dual is also true — this holds in Boolean algebra (that is why every law above comes in a pair). E.g. dual of x + 0 = x is x·1 = x; dual of x + x'y = x + y is x(x'+y) = xy.

CarefulThe dual of an expression is not equal to the expression. Duality gives you a second true theorem, not an equality between f and fd. (Don't confuse with complement: f' = fd with every variable complemented.)

5.6 Strategy when simplifying

  1. Look for common factors; apply x+x'=1 and xy+xy'=x.
  2. Apply absorption and x+x'y = x+y repeatedly.
  3. Use consensus to kill redundant terms.
  4. If it gets messy, switch to a K-map (Section 7) — it is mechanical and gives the minimum.
  5. To prove an identity, work on the more complicated side only, or evaluate both sides with a truth table.

6. Minterms, Maxterms & Canonical Forms

Any Boolean function can be written in two standard ("canonical") forms in which every term contains every variable:

  • SOP — Sum of Products (OR of AND terms) built from minterms.
  • POS — Product of Sums (AND of OR terms) built from maxterms.

6.1 Definitions

Minterm mi — a product (AND) of all variables, each variable in true form if its bit is 1 and complemented if its bit is 0. It equals 1 for exactly one input combination (number i).
Maxterm Mi — a sum (OR) of all variables, each variable in true form if its bit is 0 and complemented if 1. It equals 0 for exactly one combination.
Relation: Mi = (mi)' and mi = (Mi)'.

Your notes' shortcut: SOP (·) → "choose 1" (read the rows where f = 1); POS (+) → "choose 0" (read the rows where f = 0).

A canonical form is long. We want a minimal SOP/POS (fewest terms, then fewest literals) — found with K-maps (next section).

7. Karnaugh Maps (K-maps)

A K-map is a graphical truth table arranged so that physically adjacent cells differ in exactly one variable. Merging adjacent 1s applies xy + xy' = x visually, giving the minimal SOP without algebra.

7.1 Layout

  • n variables → 2n cells. Each cell = one minterm; the small number in the corner of each cell below is the minterm index.
  • Row/column labels follow Gray code — 00, 01, 11, 10 (not 00,01,10,11!) so neighbours differ by one bit.
  • The map is a torus: the left edge is adjacent to the right edge, the top edge to the bottom edge, and the four corners are mutually adjacent.

7.2 Rules for grouping

  1. Groups contain only 1s (or X's — see don't cares) and are rectangles (including wrap-around).
  2. Group size must be a power of 2: 1, 2, 4, 8, 16. No diagonals, no L-shapes.
  3. Make each group as large as possible (a largest possible group = a prime implicant, PI).
  4. Cover every 1 using the fewest groups. Start with 1s that can be covered by only one PI (essential PIs), then cover the rest.
  5. Groups may overlap; a group that is entirely covered by others is redundant — drop it.
  6. Reading a group: a variable that is constant in the group appears in the product (as x if constant 1, x' if constant 0); variables that change inside the group disappear. A group of 2k cells eliminates k variables.

8. Codes

A code is a systematic way to represent symbols (here, decimal digits or numbers) by bit patterns. Different codes are chosen for ease of arithmetic, error reduction, or hardware simplicity.

8.1 Classification

Codes ├─ Weighted (each bit position has a fixed weight; value = Σ weight × bit) │ ├─ Positively weighted : 8 4 2 1 (BCD), 2 4 2 1, 5 2 1 1 │ └─ Negatively weighted : 8 4 −2 −1, 6 4 2 −3 (some weights are negative) └─ Non-weighted (no positional weights) : Excess-3 (XS-3), Gray

8.2 Weighted codes and BCD

BCD (Binary Coded Decimal, 8421) writes each decimal digit 0–9 as its 4-bit binary value. A multi-digit number is coded digit by digit: 92 → 1001 0010 and 69 → 0110 1001 (your notes). It is not the same as the binary value of 92 (1011100). Codes 1010–1111 are invalid in BCD (6 wasted combinations) — they become don't cares in design.

How to choose weights for a valid decimal code (your notes)

  • The sum of all weights must be at least 9 (otherwise 9 cannot be made).
  • There must be a weight of 1 (so that the digit 1 can be represented).

Examples that work: 8 4 2 1 (sum 15), 2 4 2 1 (sum 9), 5 2 1 1 (sum 9).

8.3 Self-complementary codes

DefinitionA decimal code is self-complementary if the 9's complement of a digit is obtained by simply inverting all four bits of its code word: code(9−N) = (code(N))'. Useful because decimal subtraction by 9's complement needs no extra circuit.
Condition (weighted codes): the weights must add up to exactly 9. So 2421, 5211, 8 4 −2 −1, 6 4 2 −3 and (non-weighted) Excess-3 are self-complementary; 8421 BCD is not (sum = 15).

9. Combinational Circuits & Building Blocks

A combinational circuit is a digital circuit whose outputs depend only on the present inputs (no memory, no feedback). Contrast: a sequential circuit has memory (flip-flops). Design procedure: (1) read the specification, (2) make a truth table, (3) simplify each output with K-maps, (4) draw with gates. Standard MSI blocks are the multiplexer, demultiplexer, encoder, decoder and the adders.

Multiplexer

2n data inputs → 1 output; n select lines choose which input passes. "Data selector".

Demultiplexer

1 input → one of 2n outputs; n select lines choose which output gets the data. "Data distributor".

Encoder

2n input lines → n-bit binary code (the number of the active line). Enable E.

Decoder

n-bit code → 2n lines, exactly one active ("minterm generator"). Enable E.

An Enable pin allows the block to work only when asserted: high-enabled → E, low-enabled → Ē (bar) (your note "for noise").

9.7 MUX tree

Bigger multiplexers are built from smaller ones in a tree: the low-order select lines drive the first level, the high-order select lines drive the next level.

  • 8:1 from 4:1 and 2:1: two 4:1 MUXes (both with S1,S0) take I0–I3 and I4–I7; a 2:1 MUX controlled by S2 picks between their outputs.
  • 16:1 from 4:1: four 4:1 MUXes (S1,S0) feed one 4:1 MUX (S3,S2): 5 MUXes in total.
  • 2n:1 from 2:1 MUXes needs 2n − 1 MUXes.

9.9 BCD adder

BCD stores one decimal digit in 4 bits. If we add two BCD digits with a binary adder, the result is right only while the sum is ≤ 9. Your notes' examples:

2 + 9: 0010 + 1001 = 1011 → 1011 is not a valid BCD digit (it's 11) 7 + 9: 0111 + 1001 = 1 0000 → carry 1 and digit 0000 — but 7+9 = 16, expected 0001 0110

Why? 4 bits have 16 combinations but a decimal digit wraps at 10. Six codes (1010–1111) are skipped. So whenever the binary sum is ≥ 10 we are "6 short" in the units digit — add 6 (0110) to skip the invalid codes and generate the proper decimal carry.

Correction rule Add 0110 when: (a) the binary adder produced a carry (K = 1: sum ≥ 16), or (b) the 4-bit sum is 1010–1111 i.e. S3·S2 = 1 or S3·S1 = 1.
X = K + S3·S2 + S3·S1 (your note: "AB + AC" form). X is also the carry-out to the next BCD digit.

Operation: Adder I adds the two digits (and the carry-in from the previous digit). If X = 1, Adder II adds 0 X X 0 = 0110 to the sum; otherwise it adds 0000. Adder II's carry-out is ignored (it only occurs when X = 1 and is already represented by X).

10.2 Common mistakes (and how to avoid them)

  • K-map labels 00,01,10,11 — must be 00,01,11,10.
  • Forgetting wrap-around groups (corners, left–right edges).
  • Groups of 3, 5, 6 — only powers of 2.
  • In POS K-map: writing the term in SOP polarity. Remember: constant 1 → complemented in the sum term.
  • Using Π(0,3,7) as the "POS of Σ(0,3,7)" — Π lists the missing minterms.
  • Using a don't-care as 1 when it doesn't enlarge any group (adds a needless term).
  • 2's-complement subtraction: not padding to equal length; mis-reading the end carry (carry → positive in both methods).
  • Gray→binary: XOR-ing with the previous Gray bit instead of the previous binary bit.
  • Reading minterm index with the wrong bit order — first variable = MSB.
  • BCD adder: forgetting that a carry out of the first adder also needs correction (e.g. 7+9).
